# 키세카츠 링크 페이지 (링크트리 대체) 설계

작성 2026-10-16, Claude. 의뢰 송태양.

## 1. 의도와 이유

키세카츠의 모든 홍보 콘텐츠(Instagram·Threads·YouTube·TikTok·Naver Clip·X)는 프로필 바이오 또는 캡션에
`https://linktr.ee/KISEKATSU` 하나를 걸어 두고, 시청자가 그 페이지에서 원하는 지점의 네이버 플레이스로
넘어가게 한다. 이것이 콘텐츠 운영의 1순위 목적이다
(옵시디언 `40 Knowledge/키세카츠 콘텐츠 목적·캡션·업로드 지침.md`).

문제는 링크트리 무료 플랜이 누적 합계만 보여 주고, 유입 채널·콘텐츠별 분석과 에이전트(MCP) 접근은 유료라는 점이다.
페이지 자체는 버튼 3개짜리 한 장이므로 직접 만들고, 분석을 우리가 갖는다.

**성공의 모습:** 태양이 분석 화면을 열면 "어느 채널(가능하면 어느 콘텐츠)에서 온 사람이 어느 지점 플레이스로
넘어갔나"가 표 하나로 보인다. 이 숫자가 다음 콘텐츠 기획의 근거가 된다.

## 2. 목표 / 비목표 / 반목표

목표
- 링크트리와 같은 역할을 하는 독립 페이지 1장. 바이오에 넣을 단 하나의 주소.
- 채널별 유입·지점별 클릭·채널×지점 교차표. 가능한 채널에서는 콘텐츠별까지.
- 비용 0원. 새 유료 구독 없음.
- 기존 링크트리 주소로 들어오는 사람도 끊기지 않게.

비목표
- 홈페이지(kisekatsu.kr)에 버튼 섹션을 붙이는 것. 이 페이지는 홈페이지와 별개로 산다.
- 메뉴·사진·소개 같은 콘텐츠. 버튼 페이지 이상이 되면 안 된다.
- 오프라인 방문·매출 추적. 플레이스 페이지 방문까지만 잰다(지침 1절).

반목표(이러면 실패)
- 바이오 링크를 눌렀는데 느리거나 깨져서 플레이스까지 못 가는 것. 페이지는 분석보다 동선이 우선.
- 분석 화면이 복잡해서 태양이 안 보게 되는 것.
- 채널을 못 가린 "직접 유입"이 대부분인 것.

## 3. 제약

- 도메인 kisekatsu.kr은 가비아 DNS. 홈페이지 저장소(mcsunny84/kisekatsu-home, GitHub Pages)는 GPT 담당이라 건드리지 않는다.
- 태양의 계정: GitHub(mcsunny84), Google(mcsunny84@gmail.com). 새 서비스 가입은 태양이 직접 해야 하므로 피한다. 같은 Google 계정 안에서 GA4 속성·Google Cloud 프로젝트·서비스 계정을 만드는 것은 새 가입으로 보지 않는다(Claude 결정).
- 소셜 앱 내장 브라우저는 리퍼러를 자주 지운다. 채널 구분은 리퍼러가 아니라 주소 꼬리표로 해야 한다.
- 대외비(계좌·토큰 등)는 저장소에 넣지 않는다.

## 5. Claude의 선택 (바꿀 수 있음)

### 5.1 호스팅: GitHub Pages, 새 저장소 `mcsunny84/kisekatsu-link`
- 정적 HTML 한 장. 빌드 도구 없음. 홈페이지 저장소와 분리.
- 가비아 DNS에 `link` CNAME → `mcsunny84.github.io` 한 줄 추가. HTTPS는 GitHub Pages가 자동 발급.
- 대안으로 고려한 Cloudflare Pages+Workers는 서버측 클릭 기록이 가능해 더 정확하지만 새 계정 가입이 필요해 제외.

### 5.2 분석: Google Analytics 4 (GA4)
- 이유: 태양의 Google 계정으로 바로 만들 수 있고 무료·무제한. 소셜 앱 내장 브라우저에서도 동작. 나중에 광고·검색 데이터와 합치기 쉬움.
- 제외한 것: Cloudflare Web Analytics(커스텀 이벤트 불가), Umami/PostHog(가입 필요, 무료 한도 있음).
- GA4 자체 화면은 태양이 보기 어렵다고 가정한다. 그래서 **우리 전용 현황판**을 따로 둔다(5.5).

### 5.3 주소 꼬리표 규칙
페이지 주소 뒤에 두 가지 꼬리표를 쓴다. 짧게 유지한다.
- `ch` = 채널. 값: `ig`(Instagram) `th`(Threads) `yt`(YouTube) `tt`(TikTok) `nc`(Naver Clip) `x`(X) `lt`(옛 링크트리 경유) `etc`. 네이버 플레이스의 홈페이지 칸은 kisekatsu.kr 그대로 두고 바꾸지 않는다(Claude 결정: 플레이스→링크→플레이스 순환과 홈페이지 SEO 영향을 피함).
- `c` = 콘텐츠 코드. 게시물 안에 링크를 넣을 수 있는 채널에서만 쓴다. 형식은 `YYMMDD-짧은이름` (예 `251016-kimchinabe`).
- 예: 인스타 바이오 `https://link.kisekatsu.kr/?ch=ig`, 유튜브 설명란 `https://link.kisekatsu.kr/?ch=yt&c=251016-kimchinabe`.
- 꼬리표가 없으면 `ch=direct`로 기록한다.
- Instagram 릴스·피드는 캡션에 링크가 안 들어가므로 콘텐츠별은 불가. 이 부분은 Instagram 인사이트(게시물별 링크 탭)로 보충한다고 현황판에 안내 문구를 둔다.

### 5.4 기록하는 이벤트
- `page_view`에 `ch`, `c`를 매개변수로 붙인다.
- 버튼 클릭 시 `store_click` 이벤트: `store`(sinnonhyeon / anguk / sinsa), `ch`, `c`. 클릭 후 이동은 `beacon` 전송으로 막히지 않게 한다.
- 두 매개변수 `ch`, `c`, `store`는 GA4에서 커스텀 디멘션으로 등록한다(안 하면 표에 안 나옴).
- 데이터 보존은 GA4 무료 최대치(14개월)로 설정한다.

### 5.5 전용 현황판
- 같은 저장소의 `/dash/` 페이지. 비밀번호 대신 **URL을 공유하지 않는 것**으로 충분하지 않으므로, GA4 Data API를 브라우저에서 직접 호출하면 키가 노출된다. 따라서 현황판은 **정적 파일로 갱신**한다: 로컬(또는 GitHub Actions 스케줄)에서 GA4 Data API로 매일 수치를 뽑아 `dash/data.json`으로 커밋하고, 페이지는 그 JSON만 읽는다. API 자격 증명은 GitHub Secrets에만 둔다.
- 보여 주는 것(이 순서): ① 기간 선택(7일/30일/전체) ② 채널×지점 교차표 ③ 채널별 조회·클릭·클릭률 ④ 콘텐츠 코드별 클릭 상위 목록 ⑤ 일별 추이 한 줄 그래프. 한국어. 모바일에서 읽히게.
- 대안으로 Looker Studio(무료)를 쓸 수도 있다. 전용 현황판이 과하다고 판단되면 빌더가 Looker Studio로 대체해도 된다. 단, 태양이 열어서 바로 ②가 보여야 한다.

### 5.6 바이오 교체와 옛 링크트리
- 새 페이지가 실기기 검증을 통과하면 Claude가 태양의 크롬(로그인된 세션)에서 각 채널의 바이오·설명란·고정 댓글 링크를 새 주소(채널 꼬리표 포함)로 직접 바꾼다. 채널마다 바꾸기 직전에 태양에게 한 번씩 확인받는다(계정 설정 변경이므로). 대상: Instagram, Threads, YouTube, TikTok, Naver Clip, X. 교체 결과는 채널별 표로 기록한다.
- 옛 링크트리는 바이오 교체가 끝나면 더 쓰지 않는다. 과도기(교체 중 며칠)에만 버튼 하나 "키세카츠 매장 보기 → `?ch=lt`"로 바꿔 두어 들어오는 사람을 새 페이지로 보내고, 교체가 끝나면 계정은 그냥 둔다(삭제는 태양 결정).

### 5.7 페이지 모양
- 지금 링크트리와 같은 단순 구성: 키세카츠 로고(홈페이지에서 쓰는 것 재사용), 짧은 한 줄("가까운 매장을 골라 위치·메뉴를 확인하세요"), 버튼 3개(지점명 + 네이버 아이콘), 맨 아래 작은 kisekatsu.kr 링크.
- 버튼 순서는 링크트리와 같게: 신논현 / 안국 / 신사. (의도적 순서인지 불명. 빌더 변경 금지, 태양만 변경)
- 라이트/다크 둘 다. 폰 폭 우선. 외부 폰트·라이브러리 없이 즉시 뜨게.
- 분석 스크립트가 늦거나 막혀도 버튼은 일반 링크로 동작해야 한다.

## 6. 빌더에게 맡기는 것
- HTML/CSS 세부, 색상(키세카츠 톤 프로필 v1 참고 가능), GA4 스니펫 구현 방식.
- 현황판 JSON 스키마, 갱신 스크립트 언어(Node 권장, 이미 설치됨), GitHub Actions 스케줄 여부.
- 사전 검증: 페이지를 올린 뒤 실제 폰 인스타 앱 내장 브라우저에서 눌러 GA4 실시간에 `ch=ig`·`store_click`이 찍히는지 확인하는 절차.

## 7. 계정이 필요한 작업 (Claude가 태양의 크롬에서 수행, 각 단계 승인 후)
1. GA4 속성 생성과 커스텀 디멘션 등록.
2. 가비아 DNS에 CNAME 한 줄 추가.
3. 과도기 링크트리 버튼 교체 → 각 채널 바이오 교체(5.6).
4. 현황판 갱신용 GA4 API 자격 증명 발급과 GitHub Secrets 등록. 키 값은 채팅·일지에 적지 않는다.
각 사이트에 로그인이 안 되어 있으면 태양이 먼저 로그인한다(Claude는 비밀번호를 입력하지 않는다).

## 8. 검증 방식 (태양 지시 2026-10-16)
- 현황판 숫자가 공개 주소에 있어도 된다(태양 확인). 전용 현황판을 공개 저장소의 `/dash/`에 둔다. Looker Studio 대안은 폐기.
- 코드는 Codex로 교차검증한다. 작업 단위마다 Claude가 구현 → `/codex:*` 공식 플러그인으로 리뷰 → 지적 사항 반영 → 기록. 설계 문서 자체도 Codex 검토를 한 번 거친다.
- 실기기 검증: 배포 후 폰 인스타 앱 내장 브라우저에서 바이오 링크 → 버튼 → 플레이스 도착, GA4 실시간에 `ch`·`store` 매개변수가 찍히는지 확인한 뒤에만 "완료"로 적는다.
